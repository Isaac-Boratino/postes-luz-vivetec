# Arquitetura do Sistema - Iluminação Pública Inteligente (Projeto IoT)

Nesta seção, é apresentada a especificação técnica detalhada da **Arquitetura do Sistema** (diagrama de blocos) para o projeto de monitoramento automatizado e detecção de falhas em postes de iluminação pública. A solução foi concebida para operar como um ecossistema IoT ponta a ponta, integrando desde o sensoriamento físico até a disponibilização dos dados em tempo real para consulta local pelos órgãos de gestão municipal.

---

### Descrição Detalhada dos Blocos do Sistema IoT

* **Sensores (Camada de Percepção e Aquisição):** Vão atuar como a entrada do sistema IoT. A camada é composta por fotoresistores (sensores LDR - *Light Dependent Resistor*), individualmente associados a cada poste de iluminação da maquete/circuito. Esses sensores funcionam baseados na variação de resistência elétrica em resposta à intensidade de luz incidente. Ligados em uma configuração de divisor de tensão com resistores fixos de 10 kΩ, os LDRs convertem os níveis de luminosidade (aceso/apagado/luz natural) em variações contínuas de tensão analógica, enviando os dados em tempo real para os pinos ADC1 do Microcontrolador. Isso possibilita ao sistema medir com precisão o estado físico da lâmpada de cada poste.

* **Microcontrolador (Camada de Processamento e Controle):** Vai atuar como o processamento do sistema IoT. O núcleo do projeto utiliza a placa **ESP32 DevKit V1**, equipada com microprocessador de dois núcleos Xtensa® 32-bit LX6 e programada na linguagem **C/C++** (utilizando o ecossistema/framework Arduino). O ESP32 realiza periodicamente a leitura dos canais analógicos dos sensores LDR e compara cada leitura a um limiar de luminosidade (`LIMIAR_LUZ`) para decidir se o poste está aceso ou apagado — decisão resolvida inteiramente de forma local, sem depender de sincronização de horário pela internet (o cenário de "noite" é simulado fisicamente na demonstração, cobrindo o LDR com uma pequena caixinha). Com essas informações, o firmware executa a lógica condicional de verificação de falhas:
  1. *Poste deveria estar aceso e está apagado:* sinaliza falha/queima de lâmpada ou interrupção elétrica.
  2. *Poste deveria estar apagado e está aceso:* sinaliza desperdício de energia elétrica por acionamento indevido.
  3. *Simulação Física de Falhas:* cada um dos 3 postes conta com um **slide switch simples (ON-OFF)**, lido digitalmente pelo ESP32 (`digitalRead`, `INPUT_PULLUP`). Diferente da chave gangorra usada em uma revisão anterior do projeto, o slide switch não comuta a alimentação do LED — ele apenas informa ao firmware que uma falha está sendo simulada manualmente naquele poste. Quando o switch está acionado, o firmware inverte por software o comando que normalmente daria ao LED (por exemplo: apaga o LED à noite, simulando lâmpada queimada; ou mantém o LED aceso de dia, simulando acionamento em horário errado). O LDR correspondente continua sendo o responsável por confirmar o estado real da luz emitida, mantendo a lógica de detecção fiel a um cenário real, onde esse switch não existiria.
  4. *Sinalização Local (Demonstração):* o próprio LED de cada poste já funciona como indicador visual do estado simulado (aceso/apagado), servindo de sinalização direta ao público durante a demonstração; esta versão do projeto não conta mais com reforço sonoro (buzzer).

* **Conectividade (Camada de Rede e Transmissão):** Será o que conecta o sistema IoT à Nuvem/App. A conectividade do projeto baseia-se na interface **Wi-Fi 802.11 b/g/n (2.4 GHz)** integrada nativamente ao SoC ESP32, operando em modo estação (STA). No dia da apresentação, essa rede será fornecida/distribuída pelo próprio professor para o grupo. A comunicação com a camada de aplicação é feita por um **servidor HTTP embutido no próprio ESP32** (`WebServer.h`), que responde a requisições feitas por outros dispositivos da mesma rede local — em especial, pelo dashboard que consome os dados dos postes.

* **Nuvem/App (Camada de Aplicação e Interface do Usuário):** Vai atuar tanto como a saída de dados quanto como a interface de acompanhamento do sistema IoT, agora sem depender de nenhuma plataforma de nuvem externa. O sistema opera através de:
  1. **Servidor Web Local + Dashboard:** o próprio ESP32 expõe um endpoint (`/api/status`) que retorna, em formato JSON, o estado atual dos três postes (leitura do LDR, se o slide switch daquele poste está simulando falha, e o estado do LED). Um dashboard HTML/CSS/JS, hospedado em outro dispositivo conectado à mesma rede local, consome esse endpoint periodicamente e exibe os dados em tempo real ao público da Feira EPA, sem depender de internet externa nem de uma plataforma de IoT em nuvem.
